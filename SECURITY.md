# Security Model and Trust Boundaries (mcp-dfa-gate v0.5.1)

## 1. Formally Verified Properties (Lean 4)
`lean/lattice_proof.lean` proves two universal theorems over all 64-bit taint-lattice policies and arbitrary-length traces (no Mathlib, no `sorry`, no `native_decide`):
1. `halted_rejects_nonempty`: Once `halted = true`, every non-empty trace is rejected.
2. `universal_non_interference`: For any `LatticeState` with taint bit `i` set and any arbitrary-length trace containing a rule with `clearance[i] = false`, `run_trace` evaluates to `false`.

## 2. Runtime Adapter Guarantees (src/mcp_sidecar.cpp)
Enforced in C++20 outside the Lean model and verified by black-box tests in `tests/test_sidecar.py`:
* Strict 7-bit ASCII transport, 1 MiB line cap, duplicate JSON key rejection, and JSON-RPC `id` type validation.
* Fail-closed method allowlist (`resources/*`, `prompts/*`, `sampling/*` are blocked).
* `tools/call` frames are reconstructed from whitelisted fields only (`path`, `command`, or `url`).
* `read_file` paths are canonicalized beneath an `O_DIRECTORY` workspace descriptor via `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS)` + `fstat(S_ISREG)`. Failures taint the session (`LABEL_SECRETS`) and refuse forwarding (`-32002`).
* `bash_workspace` allows only 10 read-only binaries and rejects shell metacharacters, `..`, `/.`, dotfiles, sensitive suffixes (`.pem`, `.key`, `.p12`, `.sql`, `.env`, `.kdbx`), flag-embedded paths, and symlinks. (Full argv-array primitives to replace shell string parsing are scheduled for v0.6.)
* **v0.5 local-filesystem pin:** the gate calls `statfs(2)` on `SAFE_PREFIX` and refuses to start unless the workspace is on a local filesystem (ext2/3/4, xfs, btrfs, f2fs, tmpfs, ramfs, overlayfs). Workspaces on NFS/CIFS/SMB/FUSE/9P/CEPH/AFS/NCP (or any unknown type) permit `mmap(MAP_SHARED)` dirty-page writeback exfiltration performed by kernel helpers, which never traverses the downstream seccomp filter. `MCP_GATE_ALLOW_NETFS=1` accepts the residual explicitly (logged loudly at startup).

## 3. Linux Kernel Syscall Mediation (MCP_GATE_SECCOMP=1)
Implemented in `include/seccomp_supervisor.hpp` and verified live on Linux in `tests/test_seccomp.py`:
* Enforces native `AUDIT_ARCH` (`SECCOMP_RET_KILL_PROCESS` on mismatch) to block 32-bit compatibility syscall number bypasses.
* Installs `SECCOMP_SET_MODE_FILTER` with `SECCOMP_FILTER_FLAG_NEW_LISTENER` on the downstream child before `execvp()` and transfers the listener FD via `SYS_pidfd_open` + `SYS_pidfd_getfd` (avoiding `SYS_sendmsg` handoff deadlocks). Supported kernel floor: **5.9**; verified on Linux 5.10 (local red-team suite) and 6.x (CI). Older kernels fail closed at handoff (spawn error, exit 3).
* **Static `-EPERM` denies (no notif cost):** `SYS_ptrace`, `SYS_process_vm_readv`, `SYS_process_vm_writev`, `SYS_kcmp`, `SYS_perf_event_open`, `SYS_open_by_handle_at`, `SYS_bpf`, `SYS_userfaultfd`, `SYS_io_setup`, `SYS_io_submit`, `SYS_io_uring_setup`, `SYS_io_uring_enter`, `SYS_io_uring_register`, and `prctl(PR_SET_DUMPABLE, 0)` (argument-checked in BPF, zero notif cost: a non-dumpable downstream would fail every fence-sweep `pidfd_getfd` with `EPERM` and silently disarm socket severance — verified live; re-enabling visibility with argument 1 stays allowed).
* **USER_NOTIF-mediated, checked against the live taint mask:** socket creation (`SYS_socket`, `SYS_socketpair`, `SYS_accept`, `SYS_accept4` — against `http_fetch` clearance) plus the v0.4 egress/execution set (`SYS_connect`, `SYS_sendto`, `SYS_sendmsg`, `SYS_sendmmsg`, `SYS_execve`, `SYS_execveat`). A tainted tree cannot create new sockets or spawn new programs. This includes connections minted by `accept()`/`accept4()` on a pre-taint listener: post-taint `accept` returns `EPERM` (pinned by test), and the sweep's `shutdown()` on the listener object aborts pending accepts and empties the queue (`EINVAL` on Linux 5.10, verified) — the guarantee does not depend on listener-shutdown semantics varying by kernel.
* **v0.5 quarantine fence (audit C1/C2; hardened v0.5.1):** when a tool call raises taint that is not cleared for both channels (or halts the lattice), the sidecar invokes `Supervisor::fence()` *before* the new taint becomes visible -- and the fence is the sole owner of that raise transition (stop, sever, store as one linearized unit; the sidecar stores only benign transitions). The fence: (0) **discovers and freezes the full descendant tree**: it snapshots `/proc`, follows ppid links from the downstream root and from the sidecar's own children (the sidecar calls `prctl(PR_SET_CHILD_SUBREAPER, 1)` before the spawn and the bit is inherited, so orphaned double-forked descendants reparent inside the tree instead of escaping to init), soft-registers and SIGSTOPs every descendant, and repeats until a round registers nobody new (stopped processes cannot fork, so the fixpoint proves no fd-holding descendant is left running -- this closes the v0.5.0 gap where a silent child holding an inherited socket, never having called a mediated syscall, was never registered and its socket survived the fence; pinned by `test_silent_child_inherited_socket_severed` and `test_orphan_silent_child_socket_severed`, both of which exfiltrate successfully against the v0.5.0 binary); (1) drains every pending notif with `-EPERM` (a drained syscall was frozen pre-execution inside USER_NOTIF, so no mediated socket creation can begin after this point) and confirms every tracked thread group is **verifiably** stopped or gone (`/proc` read errors count as unverified, never as success; zombies hold no fds and count as gone); (2) runs a **quiescing sweep** -- repeatedly duplicating every fd of every tracked process with `pidfd_getfd` and `shutdown(SHUT_RDWR)`ing every socket **object**, with outcomes classified by socket object identity (severed-new / already-severed / inert / unreachable / error), until a full pass severs nothing new with zero unreachable fds and zero errors (shutting a listener also aborts blocked `accept()`s with EINVAL); (3) stores the new taint/halt atomics (the linearization point), (4) SIGCONTs. Because `shutdown(2)` operates on the shared kernel socket object, every alias -- `dup`/`dup2`, fork copies, SCM_RIGHTS-passed descriptors -- dies with it, and unmediated `write(2)`/`writev(2)`/`sendfile(2)`/`splice(2)`/`tee(2)`/`vmsplice(2)` on severed sockets fail with `EPIPE` without any per-write interception. Verdicts (including the supervisor's `SECCOMP_IOCTL_NOTIF_RECV`, poll(0)-guarded under the same mutex since v0.5.1) and the whole fence are serialized by one mutex, so no `SECCOMP_USER_NOTIF_FLAG_CONTINUE` can be issued after the taint store, and the fence drain can never race a pending RECV (the 5.10 blocking-RECV-on-empty-queue hazard is closed); syscalls that entered USER_NOTIF during the fence are frozen pre-execution and answered with the post-fence mask. If a sweep pass cannot duplicate an fd -- e.g. `pidfd_getfd` denied across a user-namespace boundary -- the fence logs a loud `FENCE WARNING`: severance is not guaranteed in that mode, while every mediated syscall still denies. A `shutdown()` that fails with `ENOTCONN` on an otherwise reachable socket is not a warning condition: an unconnected socket cannot transmit without the mediated `connect`/`sendto`/`sendmsg` anyway (raw `write` returns `EDESTADDRREQ`) -- inert by construction; connected streams and listening sockets shut down cleanly (ground-truth probes, Linux 5.10).
* **Linearization contract:** a byte can leave the host only if its write syscall completed (queued to the socket buffer) before the fence's `shutdown()` of that socket object. Every write issued after the fence resumes fails (`EPIPE`, or `EDESTADDRREQ` on unconnected UDP which cannot transmit without the mediated `connect`/`sendto`/`sendmsg`).
* **FENCE FAILURE policy (v0.5.1, fail closed):** if any tracked thread group cannot be verifiably stopped after bounded retries (a process that never settles in `T` state -- e.g. one stuck in uninterruptible `D` sleep -- or an unreadable `/proc`), or descendant discovery cannot converge (tracking cap exceeded), the fence stores the new taint (mediated denies still hold for every remaining process), leaves the tree SIGSTOPped -- never resumes an unverified process -- and reports failure; the sidecar then SIGKILLs the tracked tree and exits with code **43**. Severance claims are never made on an unverified freeze.
* **Fail-closed properties:** if the supervisor or sidecar dies, the listener FD closes and every mediated syscall in the tree returns `ENOSYS` (verified by test). If pid tracking hits its cap (1024), untracked pids are denied at mediation time. The fence is idempotent and re-runs on any further taint growth. The sidecar refuses to start (exit 3) under `MCP_GATE_SECCOMP=1` if `prctl(PR_SET_CHILD_SUBREAPER)` fails, because fence descendant discovery depends on it.
* Note: Linux allows only one `SECCOMP_RET_USER_NOTIF` listener per filter chain; nested container runtimes that already hold a listener will return `EBUSY`.

## 4. Out-of-Scope / Caller Responsibilities
* **Downstream `cwd` and filesystem confinement:** Deployers must confine the downstream server inside `SAFE_PREFIX` (see `scripts/run_confined.sh` using `bwrap`). Adding `--unshare-net` to the bwrap invocation removes the pre-taint localhost exfil surface entirely (it also breaks legitimate untainted networking and the live test suite, so it is not the default).
* **Path TOCTOU between gate and downstream:** Because MCP passes file paths as strings over JSON-RPC, a concurrent writer in `SAFE_PREFIX` could swap a file after the gate's `openat2` check. Mounting `SAFE_PREFIX` read-only in the downstream sandbox eliminates this window.
* **SSRF filtering:** Network egress is blocked once tainted, but internal/metadata IP filtering while untainted is a downstream responsibility.
* **Own-memory reads:** a tainted process can still read its *own* memory (`/proc/self/mem`, direct loads). Cross-process `ptrace`/`process_vm_readv/writev` are statically denied; in-process memory disclosure to the MCP client is the protocol's purpose, not a bypass. Landlock-based `/proc/<pid>/mem` restriction (5.13+) is scheduled for v0.6.
* **In-flight writes at fence time:** writes already executing in-kernel when the fence lands may complete and deliver (pre-raise semantics, bounded by the fence's SIGSTOP grace). The linearization contract above is the precise boundary.
* **Overlayfs upper layer on network storage:** the statfs pin allowlists overlayfs; if its upper layer is network-backed, the netfs residual re-appears. Operators must ensure overlay uppers are local (the same applies to any stacked mount).
* **Fence fd-sweep verification boundary:** the sweep is verified live in direct sidecar mode (`tests/test_seccomp.py`, Linux 5.10). Under `scripts/run_confined.sh` (bwrap `--unshare-pid` with an unprivileged user namespace), `pidfd_getfd` can be denied across the user-namespace boundary: the fence then emits `FENCE WARNING` and every mediated syscall still denies, but pre-raise socket objects may survive the sweep. The sweep's `pidfd_getfd(2)` also requires `PTRACE_MODE_ATTACH_REALCREDS` over the target: in direct sidecar mode the gate is an ancestor of the downstream tree, so `kernel.yama.ptrace_scope <= 1` (classic or restricted ptrace) is sufficient, but `ptrace_scope >= 2` (admin-only / no-attach) or any LSM restricting ptrace denies `pidfd_getfd` with `EPERM` even in direct mode — the fence then emits the same `FENCE WARNING` (mediated denies unaffected). Use `--unshare-net` (or run bwrap with privileges in the gate's user namespace) when post-raise severance must be guaranteed in sandboxed deployments; a bwrap-mode fence test is tracked for v0.6.
* **Dumpability via credential changes:** `prctl(PR_SET_DUMPABLE, 0)` is statically denied (the trivial one-line sweep disarm), but a credential change — e.g. `setgid` to a supplementary group — also clears dumpability and can likewise make the target unreachable to `pidfd_getfd`; the fence detects this and warns. A supervisor privilege model for the sweep (privileged helper) is scheduled for v0.6.
* **C++ to Lean equivalence:** `mcp_lattice::transition` and Lean `step` are matched by inspection and shared policy generation (`tools/policy_compiler.py`), not verified compiler extraction.
